# 游戏开发与 Sub-agent 工作流

主代理担任制作人和集成人，按功能交付可玩的最小纵切片；阶段以证据交接，不把 GDD / 提案当作已实现功能。每个切片自带目标等级（L0–L5）。整份游戏不设单一等级，也不另建进度数据库。未触达的职业不强制到场。同时最多三个子代理，模型与推理设置继承用户配置。

小型文档/配置由主代理完成；复杂功能按需要选角色。用户明确要求从某一级开工时，可以跳过更低等级的实现，但必须列出未覆盖项，不能把低等级说成已完成。

L0–L5 描述当前切片质量。里程碑（若有）说明仓库已有范围；切片等级说明这次改动做到哪一步。

## 角色边界

| 角色 | 标识 | 职责 | 写入 |
| --- | --- | --- | --- |
| 游戏设计师 | `game-designer` | 玩家操作、胜负、循环范围、边界与验收；**功能设计**（属性大类与模式，不含具体数值定稿） | 只读 |
| 数值策划 | `balance-designer` | 单位、技能、波次、经济等**具体数值**（在功能规格之后填空） | 分配的数据资源 |
| UI 设计师 | `ui-designer` | 信息层级、状态、文案、1920×1080 与小窗、色盲不只靠颜色 | 只读 |
| 游戏美术师 | `game-artist` | 风格、剪影、可读距离、资产简报 | 分配的概念/资产简报 |
| 游戏程序 | `gameplay-engineer` | 玩法系统、场景与 UI 行为 | 写入白名单 |
| 技术美术师 | `technical-artist` | 2D 精灵、图标、导入、相机、缺失回退与性能 | 分配的资产/表现文件 |
| 音效 | `audio-designer` | 事件表、响度、占位与正式音频资源 | 分配的音频与 cue 文档 |
| QA | `qa-tester` | 按目标等级收集证据并给出是否达到该级 | `.artifacts/` 日志 |
| 审查 | `reviewer` | 读 diff，查回归、UID、枚举、共享状态和验证缺口 | 只读 |
| CI/CD | `pipeline-engineer` | 本地与远端同一验证入口 | 管线白名单 |

主代理不新增制作人子角色。游戏设计师不改 `.tres`，讨论属性时与数值分离：先定「有哪些属性 / 哪些模式」，具体点数与默认值由数值策划填写。场景与控件实现归程序。游戏美术师不改导入、着色器和玩法脚本。技术美术师风格听美术师，界面结构听 UI 设计师。程序不改 CI 来放行，不覆盖美术原文件。QA 不改业务代码和断言。审查不替代游玩。

`pipeline-engineer` 是唯一可改 `.github/workflows/`、统一验证脚本和验证文档的角色。不要新建空流水线冒充通过。不删断言，GUI 证据不写进 CI。

## 设计文档与 Sub-agent 养成规范

子代理与主代理写设计文档时遵守：

1. **只写当前要做的事**：当前版本不做的玩法、已否决方案、纯远期脑暴，**默认不写进**愿景 / Features 等规格文档。
2. **例外**：用户明确要求保留；或实现上必须防回归。此时用**一句**说清，不展开候选对比、不堆「非目标清单」。
3. **提案归提案**：未立项内容留在对话里，或写入 Content 草案并标明未实装；**不要**为了「以后可能做」在愿景里占整节。
4. **未决列表要短**：只保留实现前必须拍板、且与当前循环直接相关的项。数值可后定的参数用「可配置 / 默认值」写在规则旁，不必单开未决条目。
5. **As-Is / To-Be**：文档定稿 ≠ 代码已对齐；新循环写 To-Be 时标明。
6. **角色短合同**：`.cursor/agents/*.md` 只写本职边界与当前玩法约束，不复制本表长文；玩法表述与落盘愿景冲突时以愿景为准并回写角色文件。

```text
主代理制作人
  → 切片合同与目标等级
      → 设计 / UI / 美术 / 音效 / 数值
          → 程序与技术美术
              → QA 与审查
                  → 主代理收回
现有 test runner 为 QA 提供本地入口，不替代 GUI 证据。
```

## 验收方式（轻量 / 完全）

与 L0–L5 **正交**：L 级描述切片质量目标；验收方式描述代理侧要跑多深。用户提出需求时，主代理**必须先问**用哪种（未指定则先问再动手）。

| 方式 | 代理侧出口 | 不做 | 效果 / 画面 |
| --- | --- | --- | --- |
| **轻量验收** | 项目能加载即过：`bash tools/run_light_verify.sh`（import + 关键场景 instantiate，无 SCRIPT/Parse Error） | 不跑完整 `run_verify_runners.sh`；不派 `qa-tester` GUI；不用 `gui-acceptance`；不收集截图/录屏当门禁 | **由用户本人验收**；代理交付时标明「轻量验收，效果未代验」 |
| **完全验收** | 与现行流程一致：相关 `*_test_runner.gd` / `run_verify_runners.sh`、按目标 L 级派 QA/审查，UI 改动走 GUI 证据 | — | 代理按 L 级收集证据后才可声称达到该级 |

规则：

1. **开需求先问验收方式**；写入切片合同字段 `验收方式：轻量 | 完全`。
2. 轻量模式下**不得**自称达到 L3+（除非用户书面确认效果）；最多报告「实现完成 + 轻量加载通过，待用户效果验收」。
3. 完全模式才派 `qa-tester` / `gui-acceptance`；轻量可省略 QA，审查可选（只扫明显回归）。
4. 轻量通过 ≠ 玩法/手感通过；用户发现问题再开缺陷切片。

## L0–L5 出口

升级靠证据，不靠角色自称。在**完全验收**下：QA 给出等级结论，审查确认没有阻断问题，主代理记录。轻量验收不替代用户效果确认。

| 等级 | 名称 | 出口证据 |
| --- | --- | --- |
| L0 | 概念 Concept | 书面玩家目标、非目标、操作、风险，以及 UI / 美术 / 音效清单。禁止写成已实现。 |
| L1 | 初稿 First Pass | 默认流程或标明的原型里能看到占位，并附占位清单。 |
| L2 | 功能性 Functional | 规则能走通；受影响的 `*_test_runner.gd` 通过。模型和声音仍可以是占位。 |
| L3 | 功能完成 Feature Complete | 合同内的边界、失败、重开和数值资源化都在；QA 无未处理的功能阻断。 |
| L4 | 可展示 Presentable | GUI 证据覆盖 1920×1080、关键界面可读、图标回退。Headless 通过不够。产物放 `.artifacts/`，不提交。 |
| L5 | 可发售 Ship | 只修缺陷。合同写明禁止新功能；相关 runner 为绿，已知问题已分级。 |

### 各角色在等级上的职责

| 角色 | L0 | L1 | L2 | L3 | L4 | L5 |
| --- | --- | --- | --- | --- | --- | --- |
| 游戏设计师 | 目标、非目标、操作、验收、风险 | 对照占位核对范围是否漂移 | 对照可走通规则核对验收 | 核对边界、失败、重开是否在合同内 | 对照可展示体验标出设计缺口 | 只读确认缺陷修复未改玩法意图 |
| 数值策划 | 列出要动的资源和公式 | 占位数值与预期区间 | 资源化并可被验证读取 | 固定 seed 量化预期齐备 | 节奏与可读性对照实测 | 只修数值缺陷，不改公式方向 |
| UI 设计师 | HUD/状态/文案/无障碍清单 | 对照占位标注信息缺口 | 对照功能流标注缺失状态 | 全部合同状态有文案与层级 | 分辨率、色盲、可读性清单 | 只读确认缺陷未破坏信息层级 |
| 游戏美术师 | 风格、剪影、可读距离简报 | 概念或灰盒占位 | 占位资产可辨认 | 合同资产到位或明确缺失回退 | 展示距离可读，风格统一 | 只修资产缺陷，不扩题材 |
| 游戏程序 | 接口与范围估计 | 默认可看到占位行为 | 规则走通，相关 runner 通过 | 边界/失败/重开落地 | 接好表现接口，不挡 GUI | 只修缺陷，禁止新功能 |
| 技术美术师 | 导入、图标、回退风险 | 占位精灵/图标能进场景 | 导入与拾取不挡功能 | 图标、回退按合同 | 相机、缩放、性能有 GUI 证据 | 只修导入/表现缺陷 |
| 音效 | cue list 与响度原则 | 事件名与占位触发点 | 功能事件可挂占位音 | 合同事件齐全 | 不盖过 UI，有听感证据 | 只修音频缺陷 |
| QA | 记录清单是否完整 | 确认占位可见并记下清单 | 跑相关 test runner | 功能阻断清零 | 收集 GUI/音频证据并给等级结论 | 相关 runner 为绿，问题已分级 |
| 审查 | 只读范围与冲突 | 占位是否误称为完成 | 验证缺口与共享状态 | 回归、UID、枚举、资源引用 | 证据与声称是否一致 | 已知问题分级，无未处理阻断 |
| CI/CD | 说明现有 runner，不假装有统一入口 | 占位不进管线冒充通过 | 受影响 runner 可复现 | 断言覆盖合同功能 | GUI 证据不写入 CI 通过条件 | 未建统一入口前不声称 L5 管线为绿 |

L5 派发给程序、美术、技术美术和音效时，范围锁死为缺陷修复。

## 文件所有权与交接

需求和接口明确后，玩法与独立美术/音效可并行；设计、接口依赖、集成、验收顺序执行。QA 和 reviewer 可并行读取同一冻结版本，期间不改被验收文件。
